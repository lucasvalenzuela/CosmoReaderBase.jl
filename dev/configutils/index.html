Configuration Utils

Property Configuration

Use PropertyConfig to create the configuration for particle and subfind properties found in simulation files.

CosmoReaderBase.ConfigManager.PropertyConfig — Type
struct PropertyConfig{T} where {T}
    props::Dict{T,Symbol}
    identifiers::Dict{Symbol,T}
    units::Dict{Symbol,<:Tuple}
    dist_exponents::Dict{Symbol,Int}
    rownames::Dict{Symbol,NTuple}
end

Configuration struct to manage the properties in a simulation file.

It is recommended to create this configuration object in the following way (by default, T will be String):

using CosmoReaderBase.ConfigManager
c = PropertyConfig() # or PropertyConfig{String}()
add_property!(c, "POS", (h -> 1 / h.h0, u"kpc"), 1, :pos, :Coordinates, :POS)
add_property!(c, "ID", (nothing, nothing), :id, :ParticleIDs, :ID)

Attributes

  • props: Dict of the property names saved in the simulation output pointing to the default Symbol identifier, e.g. "POS" => :pos
  • identifiers: Dict of all possible Symbol identifiers pointing to the property name in the simulation output, e.g. :pos => "POS" and :Coordinates => "POS"
  • units: Dict of the format :pos => (f, unit), where f(props) is the factor used to convert simulation units to comoving units (props has the fields h0 and z); and unit is the unitful unit corresponding to the quantity, e.g. u"kpc"
  • dist_exponents: Dict of the exponential dependence on distance, e.g. :pos => 1, :vel => 1, or :rho => -3. This is necessary for the conversion between comoving and physical quantities.
  • rownames::Dict{Symbol,NTuple}: Dict of the row names of the properties, they can be used to create a NamedRowArray

CosmoReaderBase.ConfigManager.add_property! — Function
add_property!(config::PropertyConfig, prop, units, [dist_exponent], [rownames], identifiers...)
add_property!(config::PropertyConfig, prop, f, unit, [dist_exponent], [rownames], identifiers...)

Adds the property prop with the given parameters to the configuration and returns config.

Example usage:

using CosmoReaderBase.ConfigManager
c = PropertyConfig() # or PropertyConfig{String}()
add_property!(c, "POS", (h -> 1 / h.h0, u"kpc"), 1, :pos, :Coordinates, :POS)
add_property!(c, "ID", (nothing, nothing), :id, :ParticleIDs, :ID)
add_property!(c, "Zs", (nothing, nothing), (:He, :C, :O, :Ej) :zs, :GFM_Metals, :Zs)

Arguments

  • config::PropertyConfig{T}: the configuration object to which to add the property
  • prop::T: property name saved in the simulation output, e.g. "POS"
  • f::Union{Function,Nothing}: function where f(props) is the factor used to convert simulation units to comoving units (props has the fields h0 and z), or nothing if no conversion is necessary
  • unit::Union{Unitful.Units,Nothing}: unitful unit corresponding to the quantity, e.g. u"kpc", or nothing for dimensionless quantities
  • units: Tuple of the format (f, unit) as an alternative to passing f and unit individually
  • dist_exponent::Union{Integer,Nothing}: exponential dependence on distance, e.g. 1 for positional and velocity quantities, or -3 for densities. This is necessary for the conversion between comoving and physical quantities.
  • rownames::Union{NTuple{N,Symbol},Nothing}: row names of the property, for example for metals
  • identifiers::Symbol...: possible identifiers (at least one is needed) for usage when reading properties, e.g. :pos, :Coordinates, :positions, etc.

CosmoReaderBase.ConfigManager.set_units! — Function
set_units!(c::PropertyConfig, prop, units)
set_units!(c::PropertyConfig, prop, f, unit)

Modifies the units of an existing property prop in the configuration.

The property can be passed by its original name or by any of its identifiers.

Examples

using CosmoReaderBase.ConfigManager
c = PropertyConfig()
add_property!(c, "POS", (h -> 1 / h.h0, u"kpc"), 1, :pos, :Coordinates, :POS)
set_units!(c, "POS", (nothing, u"kpc")) # no little h involved

# or using the second syntax with four arguments and using one of the Symbol identifiers:
set_units!(c, :Coordinates, h -> 1000, u"pc") # default to pc instead of kpc

See add_property! about creating new properties.

Modifies the row names of an existing property prop in the configuration.

The property can be passed by its original name or by any of its identifiers.

using CosmoReaderBase.ConfigManager

CosmoReaderBase.ConfigManager.properties — Function
properties(c::PropertyConfig, available_props=nothing; private=startswith("_"))

Returns the available properties as a NamedTuple vector.

The table has the following column names:

  • prop: the property name as saved in the simulation output
  • unit: the unit of the property, or nothing if unitless
  • identifiers: the possible identifiers of the property
  • rownames: row names of the properties, else nothing
  • available: true, false, or missing, depending on whether the property is actually available for the current simulation at hand

Arguments

  • available_props: vector of properties that are available from the simulation output, used for the available column
  • private=startswith("_"): function that takes a property name and returns true if it should not be output in the table

See also CosmoReaderBase.particle_properties, CosmoReaderBase.halo_properties, CosmoReaderBase.subhalo_properties, which require the format returned here.

This is not exported.

Particle Type Configuration

Use ParticleTypeConfig to create the configuration for the particle types found in a simulation, that is gas, stars, dark matter, disk, bulge, etc.

CosmoReaderBase.ConfigManager.ParticleTypeConfig — Type
struct ParticleTypeConfig{T}
    props::Dict{T,Symbol}
    identifiers::Dict{Symbol,T}
    index::Dict{Symbol,Int}
end

Configuration struct to manage the particle types in a simulation file.

It is recommended to create this configuration object in the following way (where in this example the first number indicates the particle name, such as the 0-based index in Gadget format 2, and the second number is the 1-based index that Julia is supposed to use when indexing into arrays):

using CosmoReaderBase.ConfigManager
c = ParticleTypeConfig{Int}()
add_particle_type!(c, 0, :gas, 1)
add_particle_type!(c, 1, :dm, 2)
add_particle_type!(c, 4, :stars, 5)

Attributes

  • props: Dict of the particle type names saved in the simulation output pointing to the default Symbol identifier, e.g. 0 => :gas or "PartType0" => :gas
  • identifiers: Dict of the Symbol identifiers pointing to the particle type name in the simulation output, e.g. :gas => 0 or :gas => "PartType0"
  • indices: Dict of the 1-based indices with which Julia should access arrays, e.g. :gas => 1, :dm => 2

CosmoReaderBase.ConfigManager.add_particle_type! — Function
add_particle_type!(config::ParticleTypeConfig, prop, identifier, index)

Adds the particle type prop with the given identifier and 1-based index to the configuration and returns config.

Example usage:

using CosmoReaderBase.ConfigManager
c = ParticleTypeConfig{Int}()
add_particle_type!(c, 0, :gas, 1)
add_particle_type!(c, 1, :dm, 2)
add_particle_type!(c, 4, :stars, 5)

Arguments

  • config::ParticleTypeConfig{T}: the configuration object to which to add the particle type
  • prop::T: particle type name saved in the simulation output, e.g. 0 or "PartType0"
  • identifier::Symbol: Symbol identifier of the particle type, e.g. :gas or :dm
  • index::Int: 1-based indices with which Julia should access arrays for the particle type, e.g. 1 or 2

CosmoReaderBase.convert_sim_to — Function
convert_sim_to(a, prop::Symbol, simunits::Dict, params::AbstractSnapParams; units=:physical, unitful=false, propexp)
convert_sim_to!(a, prop::Symbol, simunits::Dict, params::AbstractSnapParams; units=:physical, unitful=false, propexp)

Returns the (in-place) property array converted from simulation to other units given by units.

This is not exported.

Arguments

  • prop::Symbol: property name to be converted, this is used to look up conversion information from simunits and propexp
  • simunits::Dict: Dict of the format prop => (func, unit), where func is a function that takes a AbstractSnapParams object as an argument and returns the conversion factor from simulation to comoving units
  • params::AbstractSnapParams: parameters of the snapshot typically containing little h and the redshift

Keyword arguments

  • units::Symbol=:physical: one of :sim, :physical, or :comoving
  • unitful::Bool=false: true if the returned scalar or array should be unitful objects
  • propexp::Dict: Dict of the format prop => n, where n is the positional dimension of the unit (e.g. 1 for positions or -3 for densities)

The supported combinations are the following:
